# Veyra Windows 0.6.0 / Android 0.2.0

Windows: полноценное меню ссылок, изображений и полей ввода; favicon во вкладках, отдельная страница `veyra://sync`, ручная зашифрованная передача закладок, проверка подписи обновлений в настройках.

Android: история и её очистка, поиск по странице, выбор Google/DuckDuckGo, сайт для ПК, удаление закладок, меню долгого нажатия, сохранение ответов-загрузок через системный выбор файла, ручной обмен закладками с Windows. Исправлено восстановление вкладок при запуске. Сборка arm64, Android 8+.

## Синхронизация

На обоих устройствах открой настройки → синхронизация. Создай аккаунт, подтверди email и войди. Укажи отдельную фразу минимум из 16 символов, одинаковую на устройствах. «Отправить» сохраняет зашифрованную копию этого устройства, «Получить» объединяет доступные копии с местными закладками. Автоматического фонового обмена и распространения удалений нет. Пароли, история, cookie и веб-сессии не передаются. После перезапуска потребуется снова войти: токены и фраза не сохраняются на диск.

Формат v1: UTF-8 JSON, PBKDF2-HMAC-SHA256 (600000, salt 16 байт), AES-256-GCM (IV 12 байт, tag 16 байт в конце ciphertext). Сервер хранит payload, ID аккаунта/устройства, платформу и время. RLS разрешает операции только владельцу. Фраза не восстанавливается через сервер.

## Обновления

Windows: настройки → проверить обновления. Клиент доверяет только манифесту Ed25519, подписанному закреплённым ключом, и ZIP с совпадающими SHA256/размером. После скачивания установка ручная. Пока манифест не опубликован, проверка прямо сообщает об этом. Подпись манифеста не является Windows Authenticode-сертификатом.

Приватный ключ обновлений и защищённая копия ключа Android находятся только в `%LOCALAPPDATA%/VeyraReleaseKeys`. Создай резервную копию этой папки в защищённом месте; не публикуй её. Android release сохраняет сертификат первой версии, а пароль хранилища усилен. Сертификат называется Preview, но уникален этому проекту; закрытый ключ не включён в исходники.

## Что проверено

Windows: 14 основных интеграционных проверок; сценарии буфера обмена; переходы/RPC; отдельные тесты меню, favicon и шифрованного объединения; отказ при неверной фразе, повреждении шифротекста и подмене подписи обновления. Supabase: реальный откатный тест двух пользователей — чтение/изменение чужих строк, вставка от чужого имени и смена владельца блокируются; security advisor без замечаний.

Android: сборка и Lint. На физическом устройстве и эмуляторе эта версия пока не запускалась. Проверка входа/передачи через настоящий пользовательский аккаунт с подтверждением email не проводилась. Нет полной реализации менеджера паролей, расширений, загрузки файлов через HTML input, камеры/микрофона и фонового синка. Сохранение файлов реализовано для внешних ответов Gecko; отдельного менеджера загрузок/паузы/возобновления пока нет.

Codex Security: частичный статический аудит Windows src без подтверждённых уязвимостей; исходники менялись во время проверки. Android, зависимости и обновления не входят в его итоговый охват. Измерение инструмента: 10113664 токена общего rollout (9776128 кэшированных), агрегат четырёх потоков, не стоимость отдельного запроса.

## Перед публичным выпуском

- Настроить собственный SMTP и подтверждение/восстановление email в Supabase. Стандартная почта пригодна для ограниченных тестов.
- Пройти ручной сценарий регистрации и Windows ↔ Android с двумя реальными устройствами.
- Проверить Android на телефоне: долгие нажатия, поиск, файлы, восстановление после закрытия, приватные вкладки.
- Опубликовать проверенные артефакты и подписанный манифест в GitHub Releases; до этого автообновление ничего не устанавливает.
- Если используется R2, включить его в Cloudflare Dashboard. На момент подготовки API отвечает `10042: Please enable R2 through the Cloudflare Dashboard`.
- Windows EXE не подписан Authenticode. Возможен системный запрос доверия при запуске.

Эта подготовка не означает, что все перечисленные ручные проверки уже пройдены.
