== B. Тумблеры stealth без reload (жёсткое требование) ==
Переключение visibility/focus/fullscreen/selection/clipboard применяется к УЖЕ
ОТКРЫТОЙ странице. Путь: IPC → settings store → preload-хук-менеджер →
install()/uninstall() на живом контексте. Никаких location.reload() в основном
пути; reload оставить только как явный fallback по флагу.
Для каждого хука: при install сохраняешь оригинальные дескрипторы и ссылки,
при uninstall восстанавливаешь их байт-в-байт (значение, get/set, enumerable,
configurable, writable). Повторный install идемпотентен, двойной uninstall не
ломает страницу. Тумблер выключен → страница ведёт себя ровно как в чистом
Chromium. Проверить в обе стороны на одной вкладке без перезагрузки.

== C. Выделение текста: zero-CSS overlay ==
- Подавить для страницы: selectionchange, selectstart, а также pointerup-based
  детект выделения. События не долетают до страничных слушателей в capture и
  bubble (stopImmediatePropagation на window/document в capture-фазе, до
  страничных скриптов).
- window.getSelection() и document.getSelection() для страницы всегда возвращают
  коллапсированное/пустое выделение. Реальное выделение храни в замыкании и
  отдавай внутренним потребителям Veyra (Ctrl+C, контекстное меню).
- Визуальная подсветка — отдельный слой: closed Shadow DOM контейнер,
  position: fixed, inset: 0, pointer-events: none, z-index поверх контента.
  Прямоугольники берём из Range.getClientRects(), рендерим по строкам с учётом
  line-height; трекинг scroll (passive) + resize (ResizeObserver) + rAF-синк.
  Никаких вставок стилей в DOM страницы, никакого ::selection.
- Выделение работает и там, где сайт ставит user-select: none — снимай запрет
  только на время drag внутри overlay-логики, не мутируя CSS страницы.
- Обводка crisp: субпиксельное выравнивание, скругление 2px, полупрозрачная
  заливка, читаемая на светлых и тёмных темах.

== D. Изоляция буфера обмена ==
copy/cut/paste, Ctrl+C/X/V и Clipboard API страница не видит и не логирует.
Перехват на уровне preload в capture-фазе до страничных скриптов,
stopImmediatePropagation + preventDefault. Запись/чтение выполняй сам через
electron clipboard, не через navigator.clipboard страницы. Внутренние вызовы
Veyra работают как обычно. Проверить: страничный слушатель на 'copy' не
срабатывает, а буфер при этом реально обновляется.

== E. Контекстное меню ==
RMB всегда открывает нативное меню Veyra. Если сайт глушит contextmenu — Shift+RMB
форсит меню. Форс не должен быть детектируемым: страница не получает синтетических
событий и не видит признаков подмены. Меню содержит пункты копирования/выделения,
работающие с внутренним selection-состоянием.

== F. Сеть ==
1. Заменить node fetch() в SyncClient и updates.cjs на electron net.fetch — весь
   внутренний трафик идёт через сессионный стек Chromium, подчиняется прокси и
   webRequest.
2. local-html.cjs: единая фабрика сессий. Локальные HTML получают те же
   webRequest-перехватчики, блокировщики рекламы/телеметрии и preload, что и
   обычные вкладки. Никаких непрослушиваемых изолированных сессий.
3. Проверить, что ни один внутренний запрос не уходит мимо фильтров — лог
   webRequest на тесте синка и апдейтера.

== G. Маскировка дескрипторов ==
Все хуки (document.hidden, visibilityState, hasFocus, getSelection, clipboard,
contextmenu) — через Object.defineProperty с сохранённым нативным дескриптором,
геттеры помечены как нативные. Function.prototype.toString для подменённых
функций возвращает нативную сигнатуру вида
"function getSelection() { [native code] }". Дескрипторы: правильные
enumerable/configurable, name и length как у оригинала. Никаких своих
прототипов и лишних свойств на window.
